# Обновлённые правила отбора «Выгодные к закупке» — 19.11.2026

Для всех оптовых поставщиков одновременно обязательны ровно три условия:
1. Текущая закупочная цена поставщика строго больше 5 000 ₸ (5 000 не включается).
2. Исключить все виды пружин по названию и категории (включая варианты «пружин…» и `spring`).
3. Доходность не ниже 50% от закупочной цены: `(цена Kaspi − закупочная цена) / закупочная цена × 100%`. Прибыль в тенге отдельно отображается с учётом настроенной комиссии и расходов.

Прежний нижний порог прибыли 1 000 ₸ отменён для этого раздела. Неподходящие строки не показывать и не добавлять после последующих импортов, сохранив исходные товары и исторические записи в базе. Подходящие сортировать по прибыли в тенге, по убыванию.

# Согласованная логика выгодных закупок — 16.11.2026

## Основной список
«Выгодные к закупке» является накопительным отчётом. Он показывает
выгодные предложения по последним сохранённым ценам, без временного отсечения
по дате прайса или проверки Kaspi. Сортировка: расчётная прибыль на единицу
делённая на закупочную цену (%), затем прибыль в тенге, по убыванию.
Архивное правило 16.11 с порогом 1 000 ₸ заменено новыми тремя условиями 19.11.2026.

## Сохранение предыдущих результатов
При первой установке архивируются все доступные сейчас совпадающие,
в наличии и прибыльные предложения по реально настроенному алгоритму
администратора. Для ранее потерянных/перезаписанных значений история
не выдумывается. До обновления прайса сервер сохраняет первый ранее
доказанный выгодный расчёт. Он не исчезает, если цена, остаток или
совпадение в следующем прайсе меняется.

«Ранее выгодный» — отдельный статус с сохранённой закупочной стоимостью,
ценой Kaspi, исходными датами и результатом расчёта. Такие строки
не используются для автоматического оформления новой закупки.

«Новый» — новый выгодный товар, обнаруженный в последней завершённой
загрузке прайса и ещё не входивший в архив. Все предложения видны
также во вкладке «Все найденные».

## Даты
Отображаются независимые поля:
- Дата прайса: сохранённая поставщиком (supplier_checked_on)
- Дата обработки: фактическое применение через импортер (processed_at)
- Дата Kaspi: фактическая дата источника (kaspi_price_checked_on)

Для старых записей без доказанного времени обработки показывать
«не зафиксировано», не подставлять дату миграции.

## Границы
- Загрузка нового прайса инициируется вручную; пересчёт математический
  по сохранённым сведениям и не инициирует поиск данных Kaspi.
- Не менять закупочные цены, запасы, истории покупок и суммы ради
  улучшения отчётности.
- Не менять автоматизацию фотографий и применимости: только вручную.
- Таблица «Все товары», склад, Kaspi-публикация и остальные процессы
  остаются на прежней логике.
- До оплаты по устаревшему прайсу уточнить цену и наличие у поставщика.
