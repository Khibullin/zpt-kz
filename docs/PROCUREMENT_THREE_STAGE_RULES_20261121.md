# ZPT.KZ — служебные правила подготовки товаров к закупке

Редакция: 21.11.2026. Для интерфейса показываются только утверждённые короткие критерии. Этот файл — пояснения к реализации, не текст пользовательского интерфейса.

## Этап 1. Выбор из прайса Omega
Источник — загруженный прайс Omega, с сохранением имени файла, даты, исходных цен и остатков. Выбор категорий или групп осуществляется пользователем. Закупочная цена от 2 000 ₸ включительно. По умолчанию выбираются товары с подтверждённым положительным остатком. Возраст автомобиля — до 20 лет по умолчанию, пользователь может изменить. Отсутствующий год отмечается как неизвестный, не подменяется догадкой. Повторный выбор категории разрешён; сохраняется номер запроса. Отдельный флаг «Исключить пружины» выключен по умолчанию и применяется как на предварительном просмотре, так и при сохранении запроса; исторические запросы без этого флага считаются включающими пружины. Пружины определяются по наименованию/категории, а не по случайному поисковому результату. Прайс и исходные товарные записи не переписываются при выборе.

## Этап 2. JSON для Apify
Генерация запросов по бренду и полному артикулу; дубликаты запросов исключать. В интерфейсе шесть городов и мультивыбор галочками, параметры экспорта передавать во все ссылки скачивания. Текущая конфигурация: Алматы, Астана, Шымкент, Караганда, Актобе, Атырау (названия/доступность необходимо сверить с конкретным используемым Apify Actor). По умолчанию все шесть отмечены. До 5 карточек на запрос, по умолчанию 2, минимум 1. Все предложения продавцов, без отзывов. Максимум 500 запросов в одном экспортируемом JSON. Лимит $10 применяется в интерфейсе Apify вручную и не обеспечивается программой экспортёра. Источники характеристик и фото — только точные страницы соответствующих товаров, а не произвольные поля выдачи.

## Этап 3. Публикация в «Выгодные к закупке»
Только закупка от 2 000 ₸ включительно, подтверждённый положительный остаток, точное совпадение бренда и полного артикула. Пружины не являются исключённой категорией; если на этапе 1 активирован флаг «Исключить пружины», сохранённый запрос не содержит их. Минимальная цена Kaspi — среди фактически подтверждённых предложений продавцов соответствующих карточек. Чистая прибыль = цена Kaspi минус комиссия минус закупочная цена минус расходы; упаковку 250 ₸ учитывать один раз, не дублировать внутри иных расходов. Доходность = чистая прибыль / закупочная цена × 100%. В список допускаются только позиции с доходностью >= 50%; сначала фильтрация полного набора, затем сортировка доходности по убыванию до пагинации. При равном проценте возможен стабильный вторичный порядок по прибыли и идентификатору. Значение прибыли в тенге не заменяет процент как главный критерий. JSON результата Apify до 200 МБ и до 50 000 карточек обрабатывается партиями по 500 с сохранением прогресса, без удаления источников при ошибке. Двухколоночные сравнения: поставщик слева, Kaspi справа, данные из разных источников не смешивать, недоступность обозначать. Сбор деталей — партиями по 50. Оригинальные цены, остатки, история проверок и выбранные закупочные позиции сохраняются. Допуск в список выгодных не равен автоматическому подтверждению комплектации/исполнения для покупки.

## Разделение интерфейсов
Весь текст правил показывать только внутри соответствующих кнопок «Правила» в трёх этапах «Подготовки товаров к закупке». Параметры загрузки 200 МБ / 50 000, пояснения характеристик и компоновки сравнения — только в документации, не в коротких правилах. Раздел «Выгодные к закупке» остаётся каталогом для выбора товаров, не экраном технической пакетной обработки.

## Контроль совместимости
Согласованные правила для первого отбора применяются к `omega_selection_requests`, включая сохранённые запросы. Для второго этапа параметры городов/карточек — в `selection_exports`; внешний Apify Actor может иметь собственные ограничения. Для третьего этапа SQL-фильтр отбрасывает доходность ниже 50% до сортировки/пагинации. Не утверждать успешное развёртывание без проверки Render и страницы сайта.
