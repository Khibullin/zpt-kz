# Согласованная ручная обработка — ЗаказАвто и Фаэтон (16.11.2026)

## Настройки
- Поставщики: ЗаказАвто, Фаэтон, чередование по партиям.
- Партия: 100 товаров выбранного поставщика.
- Операции: подтверждённая фотография, миниатюра и подтверждённая применимость.
- Приоритет: только в наличии, сначала выгодные к закупке, внутри поставщика по прибыли на единицу от большей к меньшей.
- Пропускать полностью заполненное; добавлять только отсутствующее, не пересматривать отклонённый источник без новых данных.
- Фото: точный бренд/артикул/вариант/сторона/комплектность, исходное до 800px, миниатюра около 180px.
- Применимость: проверенные модель, поколение, годы, двигатель и ограничения; никаких догадок.
- Не менять цены, остатки, склад, правила Kaspi, не использовать заблокированные источники.

## Ограничение безопасности
Действует решение manual-only от 16.11.2026 (AGENTS.md, docs/MANUAL_CATALOG_ENRICHMENT_20261116.md). Никакого cron, цикла, автозапуска при старте Gunicorn или выполнения внутри HTTP-запроса.
Согласование настроек не равно разрешению немедленно запускать производственную партию или публиковать код.

## Что существует
- procurement.views.product_processing: только read-only сводка SupplierPhotoTask.
- run_manual_photo_enrichment: ручная обработка до 100 предварительно подтверждённых фото-задач через единственный существующий процессор. Не выполняет поиск источников и не определяет применимость.
- Для применимости — отдельный импорт только экспертно проверенных доказательств.

## Необходимая backend-реализация
1. Установить реальные ID поставщиков через модель Supplier и проверить поля остатка и прибыли в актуальных моделях.
2. Добавить read-only предпросмотр 100 кандидатов с детерминированной сортировкой и идентификаторами, не запускать работу на GET.
3. Хранить checkpoint чередования ЗаказАвто/Фаэтон только после завершённого ручного запуска.
4. Сопоставить кандидатов с проверенными photo tasks; существующий обработчик не гарантирует выбор тех же 100 без фильтра по выбранному snapshot.
5. Применимость исполнять только по reviewed evidence отдельным безопасным путём, без выдуманного автоподбора.
6. Отчёт: ID партии, поставщик, начало/конец, проверено, добавлено новых фото, миниатюр, fitment-связей, уже было, пропущено, заблокировано, ошибки и источники.
7. Идемпотентность, фиксация доказательств и атомарный lock; запрет второго потребителя.
8. Только после тестов — ручная постановка одной задачи из UI с RBAC, CSRF, статусом и остановкой. Пока кнопка остаётся неактивной.

## Валидация

- Тесты отсутствия выполнения на GET и автозапуска, блокировки параллельного потребителя.
- Отдельные счётчики новых фото и применимости (done не равен добавленному фото).
