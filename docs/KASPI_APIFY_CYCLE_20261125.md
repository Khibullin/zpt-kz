## Реализация

В `/office/repricer/apify/` добавлены история firsthand/kaspi-api, подключение существующего run ID и постраничное получение сохранённого Dataset без новых поисковых запросов. Каждый прогон привязан к конкретному ACTIVE; сохраняются Input, результаты, исходная дата, статус и расходы. Повторное получение завершённого импорта не применяет его заново. Неподтверждённый результат остаётся для разбора.

Для нового поиска нужны явное подтверждение и введённый предел расходов. API получает `maxTotalChargeUsd`, `timeout=1800`, `restartOnError=false`; не более двух локальных запусков на ACTIVE. Одновременно допускается один незавершённый запуск. Неопределённый ответ POST не повторяется; такой запуск связывается с историей только при совпадении исходного задания.

Получение продолжается, пока открыта страница после запуска/подключения. После закрытия страницы можно продолжить кнопкой «Получить результаты». Отдельного worker, cron или расписания нет.

Исправлено накопление вечного минимума: новая полная проверка карточки/города заменяет прежний набор продавцов, в том числе при повышении цен или пустом списке. Прочие товары и города сохраняются. Более старый прогон не возвращает устаревших продавцов. Неполные/некорректные предложения не стирают подтверждённые цены. Минимум считается только по выбранным городам. Данные собственных цен, склад и закупки не меняются.

Добавлены десять согласованных городов в общий список и фактическое покрытие карточек по городам. Исторические импорты без записи покрытия не объявляются полными.

## Конфигурация

В существующем сервисе Render нужны `APIFY_API_TOKEN` (секрет) и, при необходимости, `APIFY_MAX_RUN_USD` (серверный предел, по умолчанию 5). Без токена элементы запуска отключены. Токен передаётся только в Authorization header, не URL, исходный код, сообщения или журнал ошибок. Конфигурация ключа не запускает поиск.
