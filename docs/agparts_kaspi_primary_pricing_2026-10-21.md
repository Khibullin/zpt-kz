# AG Parts — Kaspi-first цены на ZPT.KZ (21.10.2026)

**Утверждённое правило:** основная розничная цена нашей продукции AG Parts для ZPT.KZ и agparts.kz — **цена именно нашего предложения Kaspi** (merchant ID 30363568), за **ту же упаковку/торговую единицу**. Цены конкурентов не являются основным ценником. Брендовые карточки Kaspi остаются открытыми для сторонних продавцов.

## Статус работы

Подготовлено в отдельной рабочей ветке ZPT.KZ `feature/agparts-kaspi-primary-pricing`.

Внедрено:
- `catalog/agparts_kaspi_primary.py`: модуль проверки свежих Kaspi-предложений, точного артикула, нашего merchant, действующей прямой ссылки, последнего наблюдения и минимального оптового порога.
- `catalog/management/commands/review_agparts_kaspi_prices.py`: **только ручная** команда. По умолчанию — read-only preview. Возможность записи закрыта флагом среды и SHA256 сверенного предложения. Транзакция обновляет только `Product.price` у допущенных SKU.
- Локальные тесты на временном SQLite; без обращения к Kaspi, без фонового сбора и без изменений рабочей БД.

Обзор **не** создаёт/меняет цены Kaspi, листинги, `ProductWarehouseStock`, PP1/PP2, `ProductPriceTier`, заказы и репрайсер. Другие продавцы ZPT не затрагиваются.

## Источник наблюдений

Данные **не** из поля `ProductKaspiListing.last_known_our_price` (оно устарело с сентября) и не из таблицы `KaspiOwnPriceSnapshot` (записей по AG Parts пока нет). Сборщик `office_collector` сохраняет текущие предложения, включая **наши**, в `repricer.KaspiCompetitorOfferSnapshot`. Источник выбран по `seller_code='30363568'`, `source='office_collector'` и конкретной связке с Kaspi-листингом.

Подтверждение read-only 21.10.2026, ≈12:45 по Алматы:
- **57** активных товаров;
- **47** с наблюдением нашего предложения Kaspi за 24 часа (по 48 листингам);
- **40** цен уже равны `Product.price`;
- **7** различаются;
- **10** без актуальной наблюдаемой цены;
- конфликтующих текущих цен для одного артикула нет.

Каждое применяемое наблюдение требует одновременно: активную связь, совпадающий `merchant_sku` и `Product.article`, проверенную ссылку `https://kaspi.kz/shop/p/...` с `m=30363568&ms=true`, timestamp ссылки не старше 45 дней, нашу цену не старше 24 часов, `is_available=True` и целое положительное значение цены. При двух свежих карточках с разными ценами — отказ.

**F4J163707010 — поштучная продажа исключена по решению владельца.** Существующая запись ZPT не имеет отдельного поля количества штук в упаковке. Её цена, оптовые уровни и складские единицы исторически поштучные. **Запрещено** просто переписать 2 450 → 12 450 без отдельной конверсии «1 комплект = 4 свечи», проверки остатка в единицах комплектов и изменения любых обработчиков заказа/корзины. В данном модуле SKU заблокирован для записи на уровне бизнес-логики, даже если включить ручной `--apply`.

**M118107915** нельзя автоматически снизить до 1 790 ₸ без установленного минимального порога. У него есть две привязки Kaspi, но свежая публичная карточка только одна: `148066941`; старый листинг с ценой 2 189 ₸ не использовать.

## Как проверить без записи

В рабочем дереве ZPT.KZ, после проверки отключения production DATABASE_URL:

```powershell
python manage.py check
python manage.py test catalog.tests.test_agparts_kaspi_primary
python manage.py review_agparts_kaspi_prices
```

Последняя команда не меняет БД, печатает статусы для всех активных AG Parts и `PREVIEW_SHA256`. В GitHub CI используется изолированная тестовая SQLite.

**Только после отдельной проверки и сознательного запуска уполномоченным оператором** можно применить разрешённые позиции:

```powershell
# Только на отдельно согласованном рабочем окружении,
# после резервной копии и сверки списка READY_CHANGE.
# Установить AGPARTS_KASPI_PRICE_APPLY_ENABLED=True вручную,
# НЕ включать это постоянно и НЕ помещать в Git.
python manage.py review_agparts_kaspi_prices --apply --expected-hash "<свежий PREVIEW_SHA256>"
```

Команда проверяет снимки и цены ещё раз **под блокировкой DB строк**; изменение только одной цены на SKU (`Product.price`); при любом конфликте транзакция откатывается. После применения выключить флаг, провести контрольную сверку цен и проверить карточки ZPT.
