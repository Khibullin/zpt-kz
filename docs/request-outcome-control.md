# Контроль результата заявки

В истории `/connect/staff/request/<id>/?view=history` объединены сохранение заявки, текущий статус уведомления каждому продавцу (Telegram / ручной WhatsApp), открытия, интерес, клики, отдельное подтверждение общения и поставки, вопрос покупателю и его ответ. Статусы уведомлений отображаются по имеющимся записям, а не как выдуманные промежуточные события. Время уведомления — последнее изменение записи. Фильтры «Продавцы», «Контакты», «Результат» сохраняются. Доступ только сотруднику с правом просмотра заявок; персональные ссылки и телефон в события отправки не включаются.

Вопрос покупателю отправляется отдельным явным действием сотрудника. Telegram требует привязки и согласия покупателя; WhatsApp остаётся ручным, отметка отправки требует подтверждения сотрудника. Повторное сообщение после успешного или неопределённого результата блокируется. Автоматических напоминаний по таймеру нет.

«Не купил» ведёт к выбору закрытия или продолжения поиска. Окончательный статус сохраняется после подтверждения покупателя на соответствующем экране. Повтор одного ответа не создаёт повторное событие; исправление ответа сохраняет историю и убирает прежнюю атрибуцию покупки. Повторный поиск сам по себе не запускает повторную рассылку старой заявки.

Тесты выполняются на отдельной БД с подменой Telegram API. Реальные покупатели и продавцы не получают тестовых вопросов; статусы рабочих заявок не меняются. Приглашения продавцов отложены до появления реальной новой заявки по решению владельца от 25.10.2026.
