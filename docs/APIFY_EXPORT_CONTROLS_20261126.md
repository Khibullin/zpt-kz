# Размер партий Apify и сброс подготовки — 26.11.2026

В существующем втором блоке подготовки добавлен выбор 500 / 1000 / 1500 / 2000 поисковых запросов в JSON. Значение по умолчанию — 500. Изменение мгновенно перестраивает ссылки текущего запроса и ссылки сохранённой истории, не обновляя страницу и не сбрасывая выбор категорий. Выбранный размер записывается в адрес страницы для обновления и сохранения ссылки. Сервер принимает только четыре разрешённых значения и использует выбранный размер для вычисления границ партии. Старые ссылки без batch_size продолжают означать 500. Имена файлов с другим размером дополнены суффиксом, чтобы не перепутать состав партий.

Для 9915 запросов: 500 → 20 файлов; 1000 → 10; 1500 → 7; 2000 → 5. Состав и порядок запросов сохраняются, пропусков и повторений между партиями нет. Города и число карточек применяются к каждому скачиванию и после пересчёта. Параметр размера не добавляется в тело входа внешнего Actor: он только управляет разбиением нашего экспорта. Размер входных партий не меняет обработку входящих результатов JSON по 500 строк.

«Сбросить подготовку» отправляет POST с CSRF, убирает текущий saved_request и batch_size из адреса и возвращает к первому блоку. Очищается только подтверждение текущего предварительного отбора в сессии. Прайсы, Activity истории запросов, коммерческие данные, закупочный список и сессия загрузки результатов сохраняются. Сброс не отменяет внешние запуски Apify и не запускает запросы. История остаётся доступной.

Попутно исправлены лишние закрытия callback в прежних inline-скриптах настройки экспорта и обработки входящих партий. Проверен синтаксис всех отрендеренных inline-скриптов и нового файла JavaScript.
