# Действующие правила закупочного поиска — 28.11.2026

Решение владельца после остановки Apify: исправить правила и INPUT; платные запуски вручную владельцем. Это дополнение заменяет прежние противоречащие описания поиска по артикулу отдельно и price-asc. Применяется к Omega, Phaeton DC и ZakazAuto.

1. Отбор из неизменяемого прайса выбранного поставщика. Закупочный порог задаёт пользователь: 1000 ₸ разрешены, скрытого ограничения 2000 ₸ нет; начальное значение формы 2000 ₸. Наличие и возраст автомобиля берутся из условий запроса; неизвестная применимость требует проверки.
2. Политика category_name_article_v6: один поиск по названию детали и полному исходному артикулу; повтор номера и бренд из названия убираются, полный артикул включая суффиксы/нули сохраняется. Отдельного поиска только по артикулу нет. Если название отсутствует, используется известная категория детали; если нет ни того ни другого — подготовка останавливается с объяснением.
3. Поиск ограничен категорией Kaspi Replacement parts («Автозапчасти»). Для категорий стабилизаторов используется проверенная Anti Roll Bars («Стабилизатор, крепление»). Неопределённая подкатегория не угадывается: остаётся общий раздел автозапчастей.
4. INPUT содержит фильтрованные поисковые ссылки startUrls с text и q=:category:..., searchQueries пуст. Не добавлять одну голую ссылку категории: она запустит сбор всего раздела. Прямые ссылки известных карточек не добавляются: они обходили бы ограничение категории. Каждая ссылка INPUT должна содержать одновременно название с полным артикулом и фильтр категории.
5. Поиск сортируется по relevance: сначала кандидаты нужного артикула, а не самые дешёвые посторонние карточки. До 20 карточек на ссылку и город, все доступные продавцы (maxOffersPerProduct=0), без отзывов. После точного сопоставления выбирается минимум реальных предложений среди всех полученных подходящих карточек и городов данного запроса.
6. По умолчанию INPUT содержит до 1000 поисковых ссылок в партии; явные 500/1000/1500/2000 поддерживаются. Изменение городов меняет объём исполнения, но не число файлов. Технические партии приёма результатов по 500 строк — отдельный механизм.
7. Кнопка формирования для прежнего запроса создаёт новую исправленную копию с тем же исходным прайсом, условиями и выбранными товарами; повторное нажатие не плодит копии. История старых запросов/результатов сохраняется, прямой экспорт старого небезопасного INPUT блокируется с объяснением. Старые скачанные JSON использовать заново нельзя.
8. Бренд и полный артикул сверяются по самой карточке, не по поисковой строке. Пробелы/тире в SKU игнорируются; L/R и все буквы/цифры значимы. Совпавшее название или категория сами по себе не доказывают совпадение артикула/исполнения. Исключаются явные противоречия стороны, оси и комплектности; неизвестное проверяет менеджер.
9. Новый расчёт связан с ID запроса и SHA исходного прайса. Закупочная цена, наличие и дата — из этого прайса; Kaspi — из новых результатов. Минимум объединяется по всем файлам нового запроса; чужие поставщики, SKU и старые цены не примешиваются. Ручные исправления со скриншота защищены.
10. Финансовые условия выгодности сохраняются: доходность от 50% после комиссии/расходов, упаковка 250 ₸ учитывается один раз. Исходный каталог, склад, история и закупочные заказы не переписываются. Повторное применение не создаёт дублей.
11. Ограниченная выдача не доказывает минимум всего Казахстана. Не найдено — не означает отсутствует. Перед закупкой менеджер проверяет текущую цену, исполнение и возможность заказа. Отзывы не являются продажами.

Проверка транспорта: документация https://apify.com/firsthand/kaspi-api/input-schema допускает поисковые ссылки с фильтрами. Фильтры :category:Replacement parts и :category:Anti Roll Bars проверены в живом интерфейсе Kaspi 28.11.2026. Запуск актёра для проверки не выполнялся; полнота/применение фильтра самим актёром подтверждается только контрольным запуском владельца.
