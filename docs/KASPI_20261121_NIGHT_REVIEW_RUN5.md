## Выполненные новые изменения в staging

1. Ужесточён `procurement/strict_apify_prepublication.py`: если `sellersCount` отсутствует, недостоверен либо **не равен** количеству реально полученных `offers`, карточка не считается доказательством минимальной цены. Прежняя версия защищала от `sellersCount > len(offers)`, но могла принять отсутствие счётчика или обратное расхождение. Это fail-closed защита от обрезанных/противоречивых выгрузок; иной неполный поиск по всем городам также остаётся неподтверждённым.
2. Для нескольких карточек **одного полного артикула** с одной минимальной ценой добавлены `equal_minimum_card_ids` и флаг `needs_identity_choice=true`. Детерминированный выбор ID для отображения НЕ равен доказательству эквивалентного исполнения, фотографии, применимости и комплектности.
3. В `procurement/test_strict_apify_prepublication.py` исправлена базовая фикстура с `sellersCount=1` и добавлены **3 отдельных теста**: отсутствие счётчика, счётчик меньше полученных офферов, два равноценных ценовых ID с обязательным статусом проверки исполнения.
4. Изменены только два staging-файла на ветке, коммиты `eaed1d47bfa5e754852e51663fd45539dc394d4e` и `0351b7bf6b1473ba1a2194f788e8376856e9fc51`. Workflow на ветке не даёт подтверждённого результата в доступных GitHub status/workflow-run ответах; **CI не заявлен пройденным**.
