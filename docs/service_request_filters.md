# Фильтр заявок СТО / детейлинга

Утверждён 19.10.2026. Общий интерфейс с продавцами запчастей: транспорт, марки, модели каждой марки, перечень работ. Для СТО и детейлинга отдельные списки из действующей формы покупателя. Значения JSON сохраняются только после подтверждения владельцем. Неизвестный транспорт нужно выбрать; существующие известные услуги предвыбраны.

`ServiceSeller.request_filters` — источник истины; существующая связь services синхронизируется при сохранении, кабинет и каталог показывают сохранённые параметры. Старый редактор контактов не перезаписывает подтверждённые услуги и направление. Ненастроенные организации продолжают работать по прежним правилам. «Все услуги» относится только к направлению организации. Как раньше, достаточно совпадения хотя бы одной выбранной покупателем услуги. Если указаны конкретные марки/модели, пустая или неизвестная марка/модель заявки не считается совпадением.

Подбор проверяет фильтр до районного приоритета/городского fallback. Очередь и отправщик повторно проверяют настройки. Неподходящие ожидающие отправки становятся skipped с specialization_mismatch. Изменение настроек не создаёт новых назначений, не возобновляет старые и не запускает повторные сообщения. География, режимы, остановки, приоритеты и направление не меняются.

В форме покупателя добавлен явный тип транспорта. Старые запросы API без поля и существующие заявки получают совместимое значение car; исторические очереди специально не запускаются.

Кабинет: `/service-request/filters/`, идентичность только из Django-сессии. Персональная страница `/service-request/personal/<signed-token>/`: подпись с отдельной солью, привязка к существующему ServiceMatch, срок 72 часа с формирования сообщения, CSRF при сохранении, запрет тестовых/неактивных организаций. Получатель персональной ссылки может настроить именно адресованную ему организацию, включая импортированную; это не создаёт аккаунт и не меняет пароль/контакты. Сторонняя аналитика исключена, no-store/no-referrer/noindex. Токены скрываются в сохраняемых WhatsApp-ошибках.

Отправщик сохраняет контракт текущего Meta-шаблона (7 параметров). В параметре описания передаётся начало комментария, согласованная подсказка и персональная ссылка; полный комментарий остаётся на странице. Статический текст и кнопки утверждённого Meta-шаблона не меняются. Реальные тестовые сообщения не отправлялись.

Миграция 0014 добавляет только nullable поля фильтров и тип транспорта заявки. Проверки: 147 функциональных тестов service_requests и существующих фильтров продавцов, JS DOM-проверка переключений и сохранения, Django check и makemigrations --check. Исторический тест отката миграции 0008 исключён: настройки settings_ui_ci создают схему без журнала миграций, поэтому его MigrationExecutor повторно создаёт django_content_type. Проверка наличия/согласованности новой миграции выполнена отдельно. Браузерный визуальный тест не выполнен (Chromium недоступен); адаптивная форма использует уже внедрённые CSS/JS продавцов.
