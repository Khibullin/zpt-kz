# Фильтр заявок СТО / детейлинга

Утверждён 19.10.2026. Общий интерфейс с продавцами запчастей: транспорт, марки, модели каждой марки, перечень работ. Для СТО и детейлинга отдельные списки из действующей формы покупателя. Значения JSON сохраняются только после подтверждения владельцем. Неизвестный транспорт нужно выбрать; существующие известные услуги предвыбраны.

`ServiceSeller.request_filters` — источник истины; существующая связь services синхронизируется при сохранении, кабинет и каталог показывают сохранённые параметры. Старый редактор контактов не перезаписывает подтверждённые услуги и направление. Ненастроенные организации продолжают работать по прежним правилам. «Все услуги» относится только к направлению организации. Как раньше, достаточно совпадения хотя бы одной выбранной покупателем услуги. Если указаны конкретные марки/модели, пустая или неизвестная марка/модель заявки не считается совпадением.

Подбор проверяет фильтр до районного приоритета/городского fallback. Очередь и отправщик повторно проверяют настройки. Неподходящие ожидающие отправки становятся skipped с specialization_mismatch. Изменение настроек не создаёт новых назначений, не возобновляет старые и не запускает повторные сообщения. География, режимы, остановки, приоритеты и направление не меняются.

В форме покупателя добавлен явный тип транспорта. Старые запросы API без поля и существующие заявки получают совместимое значение car; исторические очереди специально не запускаются.

Кабинет: `/service-request/filters/`, идентичность только из Django-сессии. Персональная страница `/service-request/personal/<signed-token>/`: подпись с отдельной солью, привязка к существующему ServiceMatch, срок 72 часа с формирования сообщения, CSRF при сохранении, запрет неактивных организаций; тестовые владельцы имеют доступ. Получатель персональной ссылки может настроить именно адресованную ему организацию, включая импортированную; это не создаёт аккаунт и не меняет пароль/контакты. Сторонняя аналитика исключена. Персональная страница заявки остаётся no-store/no-referrer/noindex. Страница сохранения фильтра отдаёт Referrer-Policy same-origin, чтобы браузер передал Referer при запросе к тому же сайту; проверка CSRF сохраняется. Токены скрываются в сохраняемых WhatsApp-ошибках.

Обновление 19.10.2026, 11:20: владелец поручил аудит и выравнивание всей цепочки услуг с запчастями/авторазборами. Новый шаблон `zpt_service_request_notification_v1`: номер, направление (по заявке, не по карточке получателя), марка, модель, работы/услуги, город, комментарий; персональная подписанная ссылка в URL-кнопке «Открыть заявку». Телефон клиента доступен на странице заявки. Статический текст содержит два действия отдельными строками и предложение стоимости/сроков выполнения работ. Оригинальный комментарий полностью доступен на странице, в уведомлении — до 500 символов без добавления ссылок.

Переключение происходит только при активном локальном статусе approved и точном совпадении тела/кнопок с контрактом в notification_template.py. До подтверждения Meta сохраняется прежний отправщик. Синхронизация статуса выполняется штатной кнопкой админки. Шаблон исключён из маркетинговых кампаний. Пример URL для Meta не содержит действующих токенов. Подписанные токены также маскируются, когда провайдер возвращает их как отдельный параметр кнопки.

Страница исполнителя показывает направление заявки, заметные кнопки WhatsApp/звонка и согласованную красную кнопку фильтров. Ответ покупателю ведёт на «Открыть страницу заявки», без обещания времени ответа; отсутствие совпадений не утверждает, что в городе вообще нет зарегистрированных организаций. Текущий немедленный зелёный блок после подтверждённого сохранения, отсутствие списков/количества исполнителей, фильтры кабинета и карточки сохранены. География, подбор, режимы, тестовое получение всех заявок и обработка очередей не меняются. Старые заявки не переотправляются.

Миграция 0014 добавляет только nullable поля фильтров и тип транспорта заявки. Проверки: 147 функциональных тестов service_requests и существующих фильтров продавцов, JS DOM-проверка переключений и сохранения, Django check и makemigrations --check. Исторический тест отката миграции 0008 исключён: настройки settings_ui_ci создают схему без журнала миграций, поэтому его MigrationExecutor повторно создаёт django_content_type.
