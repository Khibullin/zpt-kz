# Карточки закупленных товаров для Kaspi

Источник — только доступные пользователю оплаченные закупки и проведённые приходы. Фото, категории, характеристики, применимость, цены и подтверждение размещения не выводятся из похожего артикула. Ручные исправления и ручные цены сохраняются при обновлении.

По умолчанию цена — минимальная свежая подтверждённая цена конкурента × 0,97, округление вверх до тенге, с нижней границей прибыли из личных настроек. При отсутствии подтверждения совпадения, полного свежего списка продавцов или расходов расчёт блокируется с причиной.

Материалы и фото дополняет существующий process_price_updates --watch, не HTTP-запрос посетителя. Один проход выполняет максимум одну сетевую задачу конкурентов/публикации и одну операцию обогащения. Поиск использует существующий BRAVE_SEARCH_API_KEY, если подключён; без него остаются исходный файл, сайт поставщика и связанная карточка Kaspi. Фото из поиска принимаются только после проверки JSON-LD Product с точными брендом и артикулом; сохраняются источник, миниатюра и оригинальный ракурс, без увеличения маленьких изображений. Сходные изображения отбрасываются.

Официальные контракты: guide.kaspi.kz/partner/ru/shop/api/goods/q3219 (импорт), q3221 (статус), q3222 (результат), q3216 (категории), q3217 (атрибуты). Импорт карточки не равен началу продаж.

## Подключение автоматической публикации

Используются существующие KASPI_API_TOKEN и KASPI_MERCHANT_ID. Для цены и наличия задаются KASPI_POINT_OF_SERVICE (настоящий код склада Kaspi), KASPI_LOCAL_WAREHOUSE (соответствующий склад учёта, по умолчанию PP2), KASPI_BASELINE_PRICE_FEED_URL (действующий полный XML магазина). Результирующая ссылка доступна на странице алгоритма. После её подключения в кабинете Kaspi установить KASPI_PRICE_FEED_CONNECTED=true. Ключи и URL с секретами не записываются в Git.

Исходный полный прайс-лист проверяется по merchantid. Добавляются только товары, отправка которых явно запрошена кнопкой и импорт которых принят Kaspi. Другие предложения сохраняются. Цена пересчитывается по текущему режиму; остаток — только фактический, для сопоставленного склада. Неподтверждённый остаток и цена блокируют обновление; устаревший/ошибочный результат не отдаётся как актуальный. Обновление строится в фоне раз в минуту, сам URL отдаёт сохранённый XML без сетевых запросов.

Товары фактически не отправляются при развёртывании кода. POST «Опубликовать на Kaspi» ставит отдельную задачу. SKU стабилен и не длиннее 20 символов. Повторные нажатия и параллельные менеджеры используют одну запись публикации. При неизвестном исходе POST повторная отправка блокируется. После приёма карточки ожидаются обновление прайс-листа и подтверждение нашего продавца и цены в публичном предложении; только затем статус «Опубликовано».

«Обновить» сохраняет предыдущий снимок при ошибке, не подтверждает совпадение товара автоматически и не меняет ручную цену. Отказ источника приостанавливает проверки на 30 минут. Автоматическая проверка и поиск никогда не обходят ограничения сайтов.
